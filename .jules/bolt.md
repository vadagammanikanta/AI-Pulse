## 2025-02-28 - Optimize keyword matching in feed ranker
**Learning:** In this environment and for this specific string/pattern replacement workload (replacing a set of characters like `-_,.:;/\` with spaces), `str.translate` is unexpectedly slower than `re.sub` (`0.707s` vs `0.290s` for 100k iterations). This contradicts generic memory advice that `str.translate` is always faster for exact character replacements. However, pre-compiling regexes and caching them globally provides a reliable ~2x speedup by avoiding runtime compilation costs during tight loops.
**Action:** When working with string character replacements on small strings, benchmark both `re.sub` and `str.translate` rather than assuming `str.translate` is always faster. Always pre-compile regexes in a global structure to avoid runtime compilation overhead.
